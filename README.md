# 2×2×2 Cube — Optimal Solver + 3D Web Renderer

Project architecture:

- `precompute/`: offline C++ exhaustive BFS
- `web/`: GitHub Pages frontend
- `docs/`: state/format documentation

## State space

The project keeps whole-cube orientation as part of the state.

- `8! × 3^7 = 88,179,840` states
- QTM: `R R' U U' F F'`
- 24 solved orientations are all treated as solved sources
- maximum optimal distance is expected to be 14

The precompute program stores one optimal move per state.

## Precompute

Requirements:

- C++17
- Recommended: Release build
- A machine with several hundred MB of free RAM

Build:

```bash
cd precompute
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

Run tests first:

```bash
./build/cube_precompute --test
```

Run the full precomputation:

```bash
./build/cube_precompute
```

On Windows/PowerShell with the default CMake multi-config generator:

```powershell
.\build\Release\cube_precompute.exe --test
.\build\Release\cube_precompute.exe
```

The final lookup table is written to:

```text
precompute/output/optimal_move.bin
```

The file is packed at 3 bits/state:

```text
0 = R
1 = R'
2 = U
3 = U'
4 = F
5 = F'
6 = solved
7 = unused/error
```

The resulting file is exactly:

```text
33,067,440 bytes
```

Copy it to:

```text
web/data/optimal_move.bin
```

for the future GitHub Pages frontend.

## Important

Do not run the full BFS before `--test` passes.

The move tables and symmetry conventions follow the standard Kociemba corner ordering:

```text
URF UFL ULB UBR DFR DLF DBL DRB
```

The renderer will use the same logical convention so that the solver and 3D animation remain synchronized.


## Included generated data

This starter bundle also contains a verified `optimal_move.bin` generated by
the full 88,179,840-state BFS.

For GitHub Pages, the intended copy is:

```text
web/data/optimal_move.bin
web/data/optimal_move.json
```

The current `web/data/` copy is already present in this bundle.


## Web frontend

The frontend is already implemented as a working static-site skeleton:

- Three.js WebGL renderer
- all 8 corner cubies rendered continuously
- diagonal orthographic view exposing U/R/F naturally
- responsive resize
- 3-bit optimal-move binary loader
- random legal state generation
- optimal solution playback
- tap/click state machine
- spring-damper entrance from above
- accelerated downward exit
- physical quarter-turn animation

Three.js is loaded as an ES module from jsDelivr. GitHub Pages can serve the
project directly as a static site; no server-side code is required.

For local testing, serve `web/` through a local HTTP server (do not open
`index.html` with `file://`, because browsers block the binary fetch).

Example:

```bash
cd web
python -m http.server 8000
```

Then open `http://localhost:8000`.
